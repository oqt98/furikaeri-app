# 再インストール時の復元メモ

このメモは、APK の入れ直しや再インストール時にデータが消えやすい問題を、どこまで改善できたかを整理するためのものです。

## いま困っていた原因

- レビュー本体は主に `AsyncStorage` に保存していた
- テーマ、言語、オンボーディング状態、リマインダー設定もローカル中心だった
- `AsyncStorage` はアプリ削除や再インストールで消えることがある

つまり、ローカルだけに置いていると、入れ直し時に戻せないことがあります。

## 今回入れた改善

- 起動時に匿名セッションを確保する
- 匿名セッションが取れたら、Supabase 上のレビュー、タグ、主要設定をローカルへ復元する
- 画面は引き続き repository 経由で読み書きする

対象:
- レビュー
- タグ
- テーマ
- 言語
- オンボーディング状態
- リマインダー設定

## どこに何を置くか

- `AsyncStorage`
  - 端末で速く開くための local cache
- Supabase
  - 再取得の元になるクラウド保存先
- repository
  - 画面から見た保存の窓口

## これでどう改善するか

少なくとも、`同じ Supabase ユーザーとして復帰できる場合` は、ローカルが空でも起動時にクラウドから戻しやすくなります。

## まだ残る制約

匿名ユーザーは、Supabase の仕様上、サインアウトや完全な再インストールで同じユーザーとして戻れない場合があります。

つまり:

- アプリ起動し直し: 戻りやすい
- 端末内キャッシュが消えたがセッションが残るケース: 復元しやすい
- 完全な再インストールで匿名セッションも消えたケース: 100% の復元はまだ保証できない

この最後の問題を確実に解決するには、将来の `後で連携` を実装して、匿名ユーザーを正式なログイン方法に結びつける必要があります。

## 実機で確認したい手順

1. Supabase 環境変数を設定してアプリを起動する
2. レビューを 1 件以上作る
3. テーマや言語を変更する
4. アプリを再起動する
5. レビューと設定が残っていることを確認する
6. 可能ならローカル保存を消した状態で再起動し、クラウドから再表示されることを確認する

## 補足

今回の実装は `完全なアカウント復旧` ではなく、`クラウド保存 + 起動時復元の最小構成` です。
次の段階では、`後で連携` の実装がこの問題の本命対策になります。
