# 初回リリース方針

このメモは、`furikaeri-app` の初回リリースで何を入れるかを固定するためのものです。

## 初回リリースの前提

- リリース対象は Android のみ
- backend ありで出す
- backend 基盤は Supabase
- 認証は 匿名開始 + 後で連携
- AI は週次 AI 要約のみ
- 課金は初回リリース対象外
- 入力の速さを優先する

## 初回リリースに入れる機能

- 日次記録
- 履歴
- カレンダー
- 基本分析
- Supabase backend 基盤
- 匿名開始
- 週次 AI 要約

## 初回リリースで入れないもの

- iOS リリース
- 課金
- AI チャット
- 複雑なアカウント設定
- 高度な有料分析

## 今あるもの

- テンプレートベースの日次記録
- 履歴一覧
- カレンダー表示
- 軽量な分析
- タグ、写真、お気に入り
- 通知設定
- Notion CSV import
- Supabase 接続土台
- 匿名認証の起動土台
- 週次 AI 要約の呼び出し土台

## これから入れるもの

- DB 設計の詳細化
- RLS と認証前提の整理
- 匿名開始から後で連携する導線
- backend 同期の詰め
- AI 要約の保存や運用整理

## 実装時の判断基準

- まず入力が速いことを優先する
- backend を入れても、画面から直接 Supabase を呼ばない
- local-first で壊れにくく進める
- 今回の初回リリース対象外を README や docs で明記する
- 将来構想を、実装済み機能として書かない
